Updated 12 November 2026. These are proposed project milestones, not an ITU endorsement or a promise of competition admission. A runnable demonstration is available now; the historical research corpus and an independently reviewed evaluation remain separate work.

| --- | --- | --- |

| 4. Evaluate on a frozen new test set | Have a reviewer prepare new cases before tuning. Compare each proposed gap against existing policy/standards text, then ask ITU for the appropriate Study Group, AI for Good or Kaleidoscope route. | Source-linked problem statement, reproducible case, comparison with existing work and a response from the relevant programme. |

## Work that can continue without the original workstation

The public engine, synthetic fixtures, separately licensed UNESCO subset, report and reproduction scripts can be inspected and developed anywhere with Python 3.10+. Recovery of the private research files is required to reproduce their historical scores, not to run the available demonstration. A private archive from the original workspace or an equivalent backup is sufficient; ongoing access to a particular computer is not required after recovery.

## Release record

For each future delivery, record one code revision, one corpus manifest, the exact commands and results, the report version, the recipient and the observed send/receipt status. Keep competition acceptance, technical validation and release completion as separate fields. A pending acknowledgement must remain pending.
